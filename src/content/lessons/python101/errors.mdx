## ชนิด Error ที่พบบ่อย (Common errors)

ชื่อ error บอกใบ้ได้มากว่าผิดเรื่องอะไร

| Error | สาเหตุที่พบบ่อย |
| --- | --- |
| `ValueError` | แปลงค่าไม่ได้ เช่น `int("abc")` |
| `TypeError` | ใช้ชนิดข้อมูลผิด เช่น string + int |
| `NameError` | เรียกชื่อตัวแปรที่ไม่มี |
| `IndexError` | index เกินขนาด list |
| `FileNotFoundError` | เปิดไฟล์ที่ไม่มี |

## อ่าน traceback

traceback คือข้อความ error ที่ Python แสดงเมื่อโปรแกรมพัง มันบอกชื่อไฟล์ เลขบรรทัด และชนิดของ error ให้อ่านจากบรรทัดล่างสุดก่อน แล้วค่อยย้อนขึ้นไปดูว่าผิดที่บรรทัดไหน

ตัวอย่างเช่น ถ้าเขียน `print(age + 1)` โดยที่ `age` เป็นข้อความ:

```text
Traceback (most recent call last):
  File "main.py", line 2, in <module>
    print(age + 1)
TypeError: can only concatenate str (not "int") to str
```

บรรทัดล่างสุด `TypeError` บอกว่าเอา string ไปบวกกับ int ไม่ได้ ส่วน `line 2` บอกว่าต้องกลับไปแก้บรรทัดที่ 2

## ข้อผิดพลาดที่พบบ่อย

- เขียน `except:` เปล่า ๆ ซึ่งจับทุก error จนไม่รู้ว่าจริง ๆ แล้วพังเพราะอะไร
- ซ่อนทุก error ด้วยข้อความกว้าง ๆ อย่าง "เกิดข้อผิดพลาด"
- จับ error ไว้แล้วไม่ได้แก้สาเหตุจริง

## แบบฝึกหัด

1. รับค่าจากผู้ใช้แล้วแปลงเป็น `int`; ถ้าผู้ใช้กรอกตัวอักษร ให้จับ `ValueError` และแสดงข้อความว่าให้กรอกตัวเลข
2. อ่านไฟล์ `data.txt`; ถ้าไฟล์ไม่มี ให้จับ `FileNotFoundError` และแสดงข้อความที่เข้าใจง่าย
3. รับเลข 2 ตัวแล้วหารกัน; ต้องจับทั้งกรณีกรอกไม่ใช่ตัวเลข (`ValueError`) และกรณีหารด้วยศูนย์ (`ZeroDivisionError`)

## สรุป

อ่าน traceback จากล่างขึ้นบน ใช้ `try/except` กับ error ที่คาดไว้ล่วงหน้า และระบุชนิด error ให้ชัด โปรแกรมจะไม่พังต่อหน้าผู้ใช้ และเราจะหาสาเหตุได้เร็วขึ้น
