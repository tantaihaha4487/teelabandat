ทำงานบน branch เสร็จแล้ว ก็ถึงเวลารวมกลับเข้าเส้นหลัก การ merge คือการรวมประวัติของสอง branch เข้าด้วยกัน

## คำสั่งหลัก

`git merge` ดึงงานจาก branch ที่ระบุเข้ามาใน branch ที่เราอยู่ตอนนี้ จะรวมเข้า `main` จึงต้อง `git switch main` ก่อน แล้วค่อยรันคำสั่งนี้

## ถ้าเกิด conflict

conflict เกิดเมื่อสอง branch แก้บรรทัดเดียวกันไม่เหมือนกัน Git เลือกเองไม่ได้ว่าจะเอาแบบไหน จึงหยุดให้เราตัดสินใจ เป็นเรื่องปกติ ไม่ได้แปลว่าทำอะไรพัง ในไฟล์จะมีเครื่องหมายแบบนี้:

```text
<<<<<<< HEAD
ข้อความบน branch ที่เราอยู่
=======
ข้อความจาก branch ที่กำลังรวมเข้ามา
>>>>>>> feature-notes
```

1. เปิดไฟล์ที่ conflict
2. หาเครื่องหมาย conflict
3. เลือกเนื้อหาที่ถูกต้อง หรือเขียนรวมทั้งสองแบบ
4. บันทึกไฟล์แล้ว commit การแก้ conflict

## จุดที่มือใหม่พลาดบ่อย

- merge โดยไม่ได้ดูก่อนว่าอยู่บน branch ไหน
- กลัว conflict จนไม่กล้าใช้ Git
- ลบเครื่องหมาย conflict ไม่ครบ

## ฝึกทำ

1. สร้าง branch ใหม่ แล้วแก้ไฟล์เดียวกันในสอง branch
2. merge กลับเข้ากัน
3. อ่าน conflict แล้วแก้ด้วยตัวเอง

## สรุป

ในงานจริงต้องเจอ merge แน่นอน ถ้าอ่าน conflict ออกและแก้เองได้ ก็จะใช้ Git ได้อย่างมั่นใจขึ้นมาก
