ทุกคนเคยแก้ไฟล์ผิดหรือ commit พลาด Git มีหลายคำสั่งให้ย้อน แต่แต่ละคำสั่งให้ผลต่างกันมาก บางคำสั่งทำให้งานหายถาวร ควรรู้ให้ชัดก่อนใช้

## คำสั่งหลัก

ใน `git revert <commit>` ให้เปลี่ยน `<commit>` เป็นรหัสของ commit ที่อยากยกเลิก ดูได้จาก `git log`

## วิธีจำง่าย

| คำสั่ง | ทำอะไร | ใช้เมื่อ | ระวัง |
| --- | --- | --- | --- |
| `restore` | ทิ้งการแก้ไขในไฟล์ | แก้ไฟล์ผิดและยังไม่ได้ `add` | การแก้ไขที่ทิ้งไปอาจกู้คืนไม่ได้ |
| `reset` | เลื่อน branch ถอยหลัง | commit พลาดและยังไม่ได้ push | เปลี่ยนประวัติ ไม่ควรใช้กับงานที่ push แล้ว |
| `revert` | สร้าง commit ใหม่ที่ยกเลิก commit เก่า | งาน push ขึ้นไปแล้ว | commit เดิมยังอยู่ในประวัติ |

`git restore file.txt` ทิ้งการแก้ไขที่ยังไม่ได้ stage ของไฟล์นั้น ไฟล์จะกลับไปเหมือนเวอร์ชันที่ stage ไว้ล่าสุด ถ้าไม่ได้ stage อะไรไว้ ก็คือเหมือนตอน commit ล่าสุด

`git reset --soft HEAD~1` ถอย branch กลับหนึ่ง commit (`HEAD~1` คือ commit ก่อนหน้าล่าสุด) แต่การเปลี่ยนแปลงยังรออยู่ใน staging area ครบ เหมาะกับตอนที่อยากแก้ข้อความ commit หรือเพิ่มไฟล์ที่ลืม ใช้ได้กับ commit ที่ยังไม่ push และยังไม่มีใครใช้ประวัตินั้นร่วมกัน

## จุดที่มือใหม่พลาดบ่อย

- ใช้ `reset` กับงานที่ push ไปแล้ว ทำให้ประวัติในเครื่องเราไม่ตรงกับของทีม
- ไม่ได้ดูผลต่างก่อนย้อน
- คิดว่า `revert` ลบ commit เดิมทิ้ง จริง ๆ แล้วมันเพิ่ม commit ใหม่ที่ทำตรงข้าม

## ฝึกทำ

1. แก้ไฟล์หนึ่งไฟล์แล้วใช้ `git restore`
2. ลอง `git revert` กับ commit ทดลอง แล้วดูผลใน `git log`

## สรุป

รู้วิธีย้อนงานแล้วก็กล้าลองมากขึ้น จำง่าย ๆ ว่า ยังไม่ push ใช้ `reset` ได้ push แล้วให้ใช้ `revert`
