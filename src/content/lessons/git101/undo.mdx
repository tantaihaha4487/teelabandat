## วิธีจำง่าย

- `restore` เอาการเปลี่ยนแปลงกลับในไฟล์
- `reset` เลื่อน pointer ของ branch
- `revert` สร้าง commit ใหม่เพื่อยกเลิก commit เก่า

`git restore file.txt` ทิ้งการแก้ไขที่ยังไม่ stage ของไฟล์นั้น การแก้ไขที่ทิ้งอาจกู้คืนไม่ได้ ส่วน `git reset --soft HEAD~1` เลื่อน branch กลับหนึ่ง commit แต่เก็บการเปลี่ยนแปลงไว้ใน staging area เหมาะกับ commit ที่ยังไม่ push ไปที่ remote และยังไม่มีใครใช้ประวัตินั้นร่วมกัน

## จุดที่มือใหม่พลาดบ่อย

- ใช้ `reset` กับงานที่ push ไปแล้วโดยไม่คิดให้ดี
- ลืมดูผลต่างก่อนย้อน
- สับสนว่า revert คือการลบ commit เดิม

## ฝึกทำ

1. แก้ไฟล์หนึ่งไฟล์แล้วใช้ `git restore`
2. ลอง `git revert` บน commit ทดลอง

## สรุป

ถ้าคุณรู้จักคำสั่งย้อนงาน คุณจะกล้าลองและไม่กลัวพลาดมากเกินไป
