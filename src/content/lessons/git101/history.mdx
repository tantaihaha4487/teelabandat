ประวัติที่บันทึกไว้มีประโยชน์ตอนย้อนกลับมาดู Git บอกได้ว่าใครเปลี่ยนอะไร เมื่อไร และของเดิมเป็นอย่างไรก่อนถูกแก้

## คำสั่งหลัก

ใน `git show <commit>` ให้เปลี่ยน `<commit>` เป็นรหัสของ commit ที่อยากดู ซึ่งหาได้จาก `git log` (ใช้แค่ 7 ตัวแรกก็พอ)

## ใช้เมื่อไร

| คำสั่ง | ใช้ตอน |
| --- | --- |
| `git log` | อยากเห็นรายการ commit ของ branch ที่อยู่ ใหม่สุดอยู่บน (เพิ่ม `--all` เพื่อดูทุก branch) |
| `git show` | อยากดูว่า commit เดียวเปลี่ยนอะไรไปบ้าง |
| `git diff` | อยากดูว่าแก้อะไรไปแล้วแต่ยังไม่ได้ `add` |

ในผลของ `git diff` และ `git show` บรรทัดที่ขึ้นต้นด้วย `+` คือบรรทัดที่เพิ่ม ส่วนที่ขึ้นต้นด้วย `-` คือบรรทัดที่ถูกลบ

## จุดที่มือใหม่พลาดบ่อย

- เปิด `git log` แล้วตกใจกับข้อความยาวเหยียด (กด `q` เพื่อออก หรือใช้ `git log --oneline` ให้เหลือ commit ละบรรทัด)
- ไม่รู้ว่าดูการเปลี่ยนแปลงได้ด้วย `diff`
- เขียนข้อความ commit ไม่บอกอะไร พอมาอ่านประวัติทีหลังก็หาไม่เจอ

## ฝึกทำ

1. ทำ commit สองครั้ง
2. ใช้ `git log --oneline`
3. ใช้ `git show` ดูรายละเอียดของ commit ล่าสุด

## สรุป

อ่านประวัติได้ก็เข้าใจงานของตัวเองได้ดีขึ้น และหาได้เร็วขึ้นว่าปัญหาเริ่มจาก commit ไหน
