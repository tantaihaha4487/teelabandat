## วิธีคิด

- `git remote -v` แสดงว่า repository นี้เชื่อมกับ remote ไหนอยู่
- `push` ส่ง commit จากเครื่องเราไปที่ remote
- `pull` ดึงการเปลี่ยนแปลงจาก remote มารวมกับงานในเครื่อง
- `fetch` ดึงข้อมูลมาดูก่อน แต่ยังไม่รวมเข้ากับงานของเรา

`git push origin main` ส่ง commit จาก `main` ในเครื่องไปที่ remote ถ้าทำงานเป็นทีม ควร push ขึ้น branch ของตัวเองแทนการ push ตรงเข้า `main`

`git pull origin main` รวม `main` จาก `origin` เข้ากับ branch ที่เราอยู่ตอนนี้ ไม่ว่า branch นั้นจะชื่ออะไร จึงควรเช็กก่อนด้วย `git branch --show-current`

## จุดที่มือใหม่พลาดบ่อย

- สับสนว่า push กับ pull ทำงานทิศไหน
- ลืมเช็ก branch ก่อน push
- คิดว่า Git กับ GitHub คือสิ่งเดียวกัน (Git อยู่ในเครื่องเรา GitHub คือเว็บที่เก็บ remote)

## ฝึกทำ

1. เช็ก remote ของ repository
2. ลอง push branch ที่สร้างเอง
3. ใช้ `git fetch` แล้วดูความต่างก่อน merge

## สรุป

เมื่อเชื่อม repository ในเครื่องกับ GitHub ได้แล้ว ก็พร้อมทำงานร่วมกับคนอื่น
