## คำสำคัญ

| คำ | หมายถึง |
| --- | --- |
| Repository | ที่เก็บประวัติทั้งหมดของโปรเจกต์ |
| Working tree | ไฟล์ที่กำลังแก้อยู่บนเครื่อง |
| Staging area | ที่พักไฟล์ที่เลือกไว้ก่อน commit |
| Commit | ภาพถ่ายสถานะของไฟล์ ณ เวลาหนึ่ง พร้อมข้อความอธิบาย |
| Branch | เส้นทางการพัฒนาที่แยกออกมา ทำงานได้โดยไม่กระทบเส้นหลัก |

staging area มีไว้ทำไม: สมมติแก้ไปสามไฟล์ แต่มีแค่สองไฟล์ที่เกี่ยวกับงานเดียวกัน เราก็ `add` แค่สองไฟล์นั้นแล้ว commit แยกไว้ ประวัติจะอ่านง่ายกว่าการบันทึกทุกอย่างรวมกัน

## ข้อผิดพลาดที่เจอบ่อย

- คิดว่า commit คือการส่งไฟล์ขึ้น GitHub จริง ๆ แล้ว commit บันทึกในเครื่องเราเท่านั้น การส่งขึ้น GitHub คือ `push`
- คิดว่า `add` คือการสร้างไฟล์ใหม่ จริง ๆ แล้วมันคือการเลือกไฟล์เข้า staging area
- ลืมดู `git status` ก่อน commit

## ฝึกทำ

1. อธิบายความต่างระหว่าง working tree กับ staging area ด้วยคำพูดของตัวเอง
2. ลองสร้างไฟล์ข้อความหนึ่งไฟล์แล้วดู `git status`

## สรุป

พอรู้ว่าไฟล์เดินทางจาก working tree ไป staging area แล้วไป repository คำสั่ง Git ส่วนใหญ่ก็จะเข้าใจง่ายขึ้น บทถัดไปจะสร้าง repository แรกกัน
