`git add` คือการเลือกไฟล์ที่จะบันทึก ส่วน `git commit` คือการสร้างภาพถ่ายของงานในช่วงเวลานั้น เมื่อใช้สองคำสั่งนี้เป็น คุณก็เริ่มทำงานกับ Git ได้จริง

## วิธีคิด

- แก้ไฟล์ใน working tree
- ใช้ `git add` ย้ายสิ่งที่ต้องการไป staging area
- ใช้ `git commit` บันทึกเป็นประวัติ

ก่อน commit ควรตรวจว่ามีอะไร staged อยู่บ้างด้วย `git status` หรือดูรายละเอียดการเปลี่ยนแปลงที่ staged ด้วย `git diff --staged`

## จุดที่มือใหม่พลาดบ่อย

- ใช้ `git add .` โดยไม่ตั้งใจใส่ไฟล์ที่ยังไม่ควร commit
- เขียนข้อความ commit สั้นเกินไป เช่น `fix`
- ลืมตรวจ `git status` ก่อน commit

## ฝึกทำ

1. แก้ไฟล์หนึ่งไฟล์แล้วรัน `git add .`
2. commit ด้วยข้อความที่อธิบายสิ่งที่เปลี่ยนจริง ๆ

## สรุป

ถ้าคุณอ่าน `git status` แล้วรู้ว่ามีอะไร staged และอะไรยังไม่ staged ก็ถือว่าเข้าใจหัวใจของ workflow ขั้นต้นแล้ว
