`git add` คือการเลือกว่าจะบันทึกไฟล์ไหน ส่วน `git commit` คือการถ่ายภาพงาน ณ ตอนนั้นเก็บลงประวัติ สองคำสั่งนี้คือสิ่งที่จะใช้ทุกวัน ใช้เป็นแล้วก็เริ่มทำงานกับ Git ได้จริง

## คำสั่งหลัก

`git add file.txt` เลือกเฉพาะไฟล์เดียว ส่วน `git add .` เลือกทุกไฟล์ที่เปลี่ยนในโฟลเดอร์นี้ (จุดหมายถึงโฟลเดอร์ปัจจุบัน) แล้ว `git commit -m` บันทึกพร้อมข้อความอธิบาย

## วิธีคิด

- แก้ไฟล์ใน working tree
- ใช้ `git add` ย้ายสิ่งที่ต้องการไปไว้ใน staging area
- ใช้ `git commit` บันทึกสิ่งที่อยู่ใน staging area เป็นประวัติ

ก่อน commit ให้เช็กว่ามีอะไรอยู่ใน staging area บ้างด้วย `git status` หรือดูว่าแก้บรรทัดไหนไปบ้างด้วย `git diff --staged`

## เขียนข้อความ commit อย่างไร

ข้อความ commit ควรบอกว่าเปลี่ยนอะไร อีกหลายเดือนข้างหน้าเราจะอ่านแค่ข้อความนี้เพื่อหาว่าแก้อะไรไปตอนไหน `Write first draft` บอกได้ชัดกว่า `fix` หรือ `update` มาก

## จุดที่มือใหม่พลาดบ่อย

- ใช้ `git add .` แล้วเผลอเลือกไฟล์ที่ยังไม่ควร commit ติดไปด้วย
- เขียนข้อความ commit สั้นจนไม่มีความหมาย เช่น `fix`
- ลืมเช็ก `git status` ก่อน commit

## ฝึกทำ

1. แก้ไฟล์หนึ่งไฟล์แล้วรัน `git add .`
2. commit ด้วยข้อความที่บอกว่าเปลี่ยนอะไรไปจริง ๆ

## สรุป

ถ้าอ่าน `git status` แล้วบอกได้ว่าไฟล์ไหนอยู่ใน staging area แล้ว และไฟล์ไหนยังไม่อยู่ ก็ถือว่าเข้าใจขั้นตอนหลักของ Git แล้ว
