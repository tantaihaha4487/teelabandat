branch คือเส้นทางทำงานที่แยกออกจากเส้นหลัก เราลองทำฟีเจอร์ใหม่บน branch ได้เต็มที่ ถ้าพังก็ไม่กระทบงานบน `main` พอเสร็จและแน่ใจแล้วค่อยรวมกลับ

## คำสั่งหลัก

`git branch` แสดงรายชื่อ branch ทั้งหมด ตัวที่มี `*` คือ branch ที่อยู่ตอนนี้ `git switch -c feature-login` สร้าง branch ใหม่แล้วย้ายไปอยู่ทันที (`-c` ย่อมาจาก create) และ `git switch main` สลับกลับไปที่ `main`

## วิธีคิด

- `main` คือสาขาหลักที่ควรใช้งานได้เสมอ
- สร้าง branch ใหม่ทุกครั้งที่เริ่มงานชิ้นใหม่ และตั้งชื่อให้บอกว่าเป็นงานอะไร
- สลับ branch ได้ตลอดเวลาเพื่อไปทำอีกงาน ไฟล์ในโฟลเดอร์จะเปลี่ยนไปตาม branch ที่เลือก

## จุดที่มือใหม่พลาดบ่อย

- สร้าง branch เยอะเกินไปและตั้งชื่อที่อ่านแล้วไม่รู้ว่าเป็นงานอะไร
- ลืมสลับกลับไป branch ที่จะรับงานก่อน merge
- คิดว่า branch คือโฟลเดอร์ใหม่ จริง ๆ แล้วไฟล์ยังอยู่ในโฟลเดอร์เดิม Git แค่สลับเนื้อหาให้

## ฝึกทำ

1. สร้าง branch ใหม่ชื่อ `feature-notes`
2. แก้ไฟล์หนึ่งไฟล์แล้ว commit บน branch นั้น
3. สลับกลับ `main` แล้วดูว่าไฟล์ที่แก้กลับเป็นแบบเดิม

## สรุป

branch ทำให้แยกงานได้อย่างปลอดภัย บทถัดไปจะรวม branch กลับเข้าหากัน
