ตัวอย่างนี้ทำครบตั้งแต่สร้าง branch ไปจนถึงส่งขึ้น GitHub `-u` ใน `git push` จำไว้ว่า branch นี้ผูกกับ branch ชื่อเดียวกันบน `origin` ครั้งต่อไปพิมพ์แค่ `git push` ก็พอ

## แนวทางพื้นฐาน

- แยก branch ตามงาน
- commit ทีละน้อย และเขียนข้อความที่บอกว่าเปลี่ยนอะไร
- เปิด pull request เมื่องานพร้อมให้คนอื่นตรวจ
- แก้ conflict อย่างใจเย็น

## คำแนะนำสำหรับมือใหม่

1. หนึ่ง branch ทำงานเรื่องเดียว
2. เขียนข้อความ commit ให้คนอื่นอ่านแล้วเข้าใจ
3. อ่านความเห็นจากการ review ให้ครบก่อน merge

## จุดที่มือใหม่พลาดบ่อย

- push โค้ดที่ยังไม่พร้อมให้ทีมใช้
- ตั้งชื่อ branch ที่ไม่บอกว่าเป็นงานอะไร
- merge โดยไม่อ่านความเห็นจากการ review

## สรุป

ใช้ branch กับ pull request เป็นระบบแล้ว การทำงานกับคนอื่นจะง่ายขึ้นมาก และพลาดน้อยลง
